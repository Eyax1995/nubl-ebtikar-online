# مواصفة (مسودة للنقاش): منصة «مؤسسة نبل وإبتكار للأعمال التجارية» (الكيان الأم)

- **أعدّها:** Cowork، بتاريخ 25 أكتوبر 2026.
- **الحالة:** المرحلة 0 (حصر وقرار). لا يُكتب كود قبل حسم الأسئلة أدناه.
- **البروتوكول:** `docs/BRIDGE.md`.

## الهدف
طبقة إدارة عليا للمؤسسة الأم، تربط الكيانات الأربعة: الدعاية والإعلان، والإنتاج الفني، والتسويق، والتقنية والأتمتة. لا تكرّر عمل منصات الكيانات، بل تقرأ منها وتوحّد:
1. السياسات واللوائح والهيكل التنظيمي والصلاحيات، وهو ما بدأه إياد في Claude Code.
2. التعاميد والاعتمادات، أي مسار موحّد للطلب ثم الرئيس التنفيذي ثم المالية.
3. التعاملات البينية بين الكيانات، مثل عقد التسويق مع الإنتاج C-2026-0002: الفواتير الداخلية والتسويات.
4. لوحة مؤشرات موحّدة: الإيراد والتحصيل والعقود والفريق لكل كيان.
5. الموظفون والرواتب والسلف على مستوى المجموعة.

## ما هو قائم (حصر 25 أكتوبر)
| النظام | المكان | ما يقدمه |
|---|---|---|
| منصة التسويق | `nubl-online` → Cloudflare Pages + D1، و`/marketing/hub` | CRM وعروض وعقود وفواتير وتوظيف وواتساب وMCP |
| نظام الطلبات PHP | `nubl-platform` | إدارة الطلبات والمحاسبة وربط «قيود» (ترقيات v19–v23) |
| مستودع nubl-ebtikar-online | محلي | نسخة أخرى من موقع التسويق؛ يجب توحيده مع `nubl-online` |

## أسئلة يحسمها إياد قبل البناء
1. **مكان عمل Claude Code على السياسات والتنظيم:** لم يُعثر عليه في المستودعات الثلاثة. ما المسار أو المستودع؟
2. **قاعدة البناء:** نوصي بمشروع Cloudflare جديد `nubl-group` بقاعدة D1 مستقلة، يقرأ من منصات الكيانات عبر API بمفاتيح خدمة. البديل توسيع منصة التسويق، ولا نوصي به لخلط الصلاحيات.
3. **المحاسبة:** هل «قيود» نظام المحاسبة المعتمد للمجموعة كلها؟ إن كان كذلك فالمنصة الأم تقرأ منه ولا تبني محاسبة.
4. **الدومين:** مثلاً `nubl-ebtikar.online/group` أو نطاق فرعي `group.`.

## المرحلة 1 المقترحة (بعد الحسم)
- **المستخدمون والأدوار على مستوى المجموعة:** رئيس تنفيذي، مالية، مدير كيان، موظف، مع دخول Google.
- **مكتبة السياسات:** إصدارات، وتاريخ نفاذ، واعتماد، وإقرار اطلاع الموظفين.
- **مسار التعاميد:** نموذج ثم اعتماد الرئيس التنفيذي ثم اطلاع المالية، وتصدير خطاب Word/PDF بقواعد RTL الثابتة.
- **لوحة مؤشرات** تقرأ من MCP منصة التسويق (hub_overview / hub_report) أولاً، ثم بقية الكيانات.

## معايير القبول (المرحلة 1)
- لا أسرار في المستودع، والمفاتيح كلها في Cloudflare.
- صلاحيات قائمة على الدور، تُختبر لكل دور.
- العرض على 390px و1366px دون تمدد أفقي.
